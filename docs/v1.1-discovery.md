# Suture 1.1 discovery surface

The binary is self-describing. A caller with no repository documentation can
use this sequence:

```text
suture help
suture capabilities --json --all
suture examples
suture schema request --json
suture suggest path/to/file --goal set-value --at SELECTOR
```

`help` explains the mental model and command map. `capabilities` reports the
runtime provider graph, operation metadata, preservation states, limits and a
`capability_set_id`. `examples` emits current protocol values; the test suite
deserializes every official example through the same Rust request types used by
execution. `schema` exposes generated request, response and transaction
schemas with a deterministic `schema_id`.

Every refusal and relevant failure certificate includes `reason_code`. Use
`suture explain REASON_CODE --json` for machine-readable recovery guidance.
For a refusal certificate saved as `refusal.json`, use:

```text
suture suggest --from-refusal refusal.json
```

Suggestions are deterministic skeletons only. They never invoke an LLM,
network, subprocess, or mutation, and they never loosen a caller's budget.
