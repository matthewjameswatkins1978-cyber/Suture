# Suture

Suture is a small, deterministic file-mutation runtime for AI agents. It makes one claim: when an operation reports `APPLIED`, the caller receives a certificate describing the observed bytes, the authorised edit ranges, structural validation, and what was actually committed.

The pipeline is `OBSERVE -> IDENTIFY -> GUARD -> MUTATE -> VERIFY -> CERTIFY`. Ambiguous or stale reality is refused; it is never silently resolved by choosing the first match.

## Install

Download the platform binary from a GitHub release and put `suture` (or `Suture.exe`) on `PATH`. Building from source requires Rust 1.85 or newer:

```text
cargo install --path .
```

## 60-second example

From the directory containing `config.txt`:

```text
echo {"version":"1.1.0","request_id":"example-1","file_path":"config.txt","cardinality":{"type":"exactly_one"},"operation":{"provider":"text","operation":{"type":"replace","target":"old","replacement":"new"}}} | suture mutate
```

Requests use explicit protocol versioning. A JSON request can target text, strict JSON, or TOML:

```json
{"version":"1.1.0","request_id":"example-2","file_path":"config.json","cardinality":{"type":"exactly_one"},"operation":{"provider":"json","operation":{"type":"set","path":"$.server.port","value":8080}}}
```

The outer `provider` selects the provider and the nested operation tag selects the typed operation. The canonical shape is generated by `suture schema`; `suture capabilities` is the machine-readable feature negotiation surface.

An applied certificate contains `outcome: "APPLIED"`, pre/post SHA-256 hashes, changed byte ranges, a bounded diff, and commit evidence. A duplicate text target returns `REFUSED` with bounded candidate offsets and context so an agent can disambiguate in one follow-up request.

```text
suture --version
suture doctor
suture capabilities
suture schema
suture preview --request request.json
suture mutate --request request.json
suture recover
```

Exit codes are `0` for `APPLIED` or `NO_CHANGE`, `2` for `REFUSED`, and `3` for runtime failure. Machine output is JSON on stdout for mutation commands; diagnostics are kept on stderr.

## Providers and guarantees

Text operations include exact byte-range edits plus idempotent desired-state operations. JSON and JSONC use source-range edits; TOML uses `toml_edit` and narrows its candidate to the changed span. YAML is deliberately conservative and refuses constructs outside its source-preserving subset. Markdown edits bounded heading sections; dotenv edits keys while preserving comments. Pattern edits use Rust's bounded regex engine. Code edits validate Tree-sitter syntax and target exact syntax-node text/kind for JavaScript/TypeScript, Python, Rust, and Go.

All providers preserve unrelated bytes in the candidate they submit to Core. Core alone commits. The workspace confines paths, rejects traversal and escaping symlinks, stages in the destination directory, flushes before replacement, rechecks the observed hash immediately before commit, and reads the committed bytes back for certification.

The v1.1 contract supports UTF-8, UTF-8 BOM, LF, CRLF, and either final-newline state; unknown legacy encodings are refused. Requests can declare hard effect budgets. Multi-file transactions stage candidates in memory, journal before commit, roll back on failure where possible, and expose recovery state. Start with `suture help`, `suture examples`, `suture schema`, or `suture suggest PATH`; Suture does not execute Git, builds, tests, formatters, subprocesses, or network operations; see [the threat model](docs/threat-model.md).
